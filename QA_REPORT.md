# BARBER CULT — отчёт о проверке

Дата: 26 октября 2026 года. Проверен локальный демонстрационный проект AI-студии NOVARY. Коммиты и публикация не выполнялись. Новые библиотеки и зависимости не добавлялись.

Это отчёт предыдущего этапа, до первого коммита и публикации. Последующая проверка GitHub Pages и подготовленные доменные SEO-метатеги описаны в [PORTFOLIO_CHECK.md](PORTFOLIO_CHECK.md).

## Результат

По выполненным проверкам блокирующих ошибок в основном сценарии не обнаружено. Проект можно размещать как статический демонстрационный сайт. Перед публичным запуском остаётся настроить доменные SEO-метатеги и выполнить проверки на реальных устройствах, перечисленные ниже. Это не заключение о полном соответствии WCAG и не результат Lighthouse.

## Найденные и исправленные проблемы

## Выполненные проверки

### HTML, SEO и доступность

- Разобраны `index.html` и `credits.html`; отдельно проверена вложенность тегов без автоматического исправления парсером.
- Проверены язык `ru`, одна H1 на каждой странице, структура header/main/footer и заголовков разделов, title, description, viewport и Open Graph.
- Проверены уникальность ID, целевые якоря, локальные ссылки, `src` и `srcset`.
- Для всех восьми размещений фотографий есть alt и правильные исходные width/height.
- Проверены доступные названия кнопок, нативный модальный dialog, сообщения деморежима и live-region отзывов.
- Проверены фокус после Escape, закрытия по фону и перехода к услугам. При Tab после последней кнопки нативный dialog позволяет перейти к интерфейсу браузера; следующий Tab возвращает фокус к закрытию диалога, фоновые элементы страницы не активируются.
- Для основных непрозрачных цветов текста на фонах #101010 и #1A1A1A рассчитан контраст: основной текст 15,57–17,02:1, вторичный 6,11–6,68:1, акцент 7,60–8,31:1. Контраст над фотографиями и все комбинации состояний этим расчётом не сертифицированы.
- Добавлено состояние фокуса для forced-colors. Системный режим высокой контрастности вручную не запускался.

### CSS и адаптивность

В Chrome измерены viewport и `documentElement.scrollWidth` на ширинах **320, 360, 390, 414, 760, 768, 820, 1024, 1280, 1470 и 1920 px**. Во всех случаях горизонтального переполнения страницы не обнаружено. Дополнительно проверены границы заголовков, строк услуг, контактов и подписей команды.

Визуально просмотрены первый экран desktop/mobile, мобильный прайс, команда, галерея и диалог на 390 px. Проверены загрузка локальных фотографий и шрифтов, сохранение кадрирования после добавления picture/WebP. На 390 px браузер выбирает `hero-small.webp`; подпись деморежима имеет размер 10 px.

Проверка последнего сценария — возврата со страницы источников и диалога на 320 px — прервалась из-за тайм-аута браузерного инструмента. Она не засчитана как пройденная. Системный масштаб 200% также не подтверждён: отправленные через инструмент горячие клавиши не изменили измеренный масштаб. Эти пункты оставлены для ручной проверки.

### JavaScript и функциональность

- `node --check script.js` — успешно.
- Открытие мобильного меню, Escape с возвратом фокуса, закрытие после выбора раздела — успешно.
- Все пять основных якорных переходов с клавиатуры — успешно.
- Выбор услуги и мастера, корректное пояснение деморежима — успешно.
- Закрытие диалога кнопкой, Escape и кликом по фону; восстановление фокуса — успешно.
- Три примера отзывов переключаются вперёд и назад, включая переходы по кругу — успешно.
- Демоокно Telegram не содержит остатка выбранной услуги/мастера и скрывает кнопку просмотра услуг — успешно. VK использует тот же обработчик.
- При недоступном скрипте: на 320 px навигация видна, якорь услуг работает, скрытых через opacity блоков нет, интерактивные кнопки отключены.
- Анимации появления просмотрены; CSS и начальная ветка JS учитывают `prefers-reduced-motion`. Реальное переключение этой системной настройки не выполнялось.
- В проверенных сценариях основного сайта консоль Chrome не содержала ошибок и предупреждений. На отдельном тестовом сервере с CSP ожидаемо блокировался script.js; это не конфигурация публикуемого сайта.

### Производительность

| Ресурсы | Исходные варианты | Оптимизированные варианты | Снижение |
| --- | ---: | ---: | ---: |
| Все 6 вариантов фотографий | JPEG: 1 675 907 байт | WebP: 763 324 байта | 54,5% |
| Два шрифта | TTF: 181 416 байт | WOFF: 86 476 байт | 52,3% |
| Первый экран mobile | JPEG: 180 960 байт | WebP: 81 626 байт | 54,9% |

Таблица сравнивает альтернативные файлы одинаковых размеров, а не полный сетевой трафик страницы. Браузер выбирает один подходящий формат и размер. JPEG/TTF остаются на диске для совместимости. Общий размер каталога поэтому вырос, хотя передаваемые посетителю ресурсы стали меньше.

Сайт не требует npm, сборки, сторонних JS-библиотек или внешних API. Размер script.js — 6 843 байта. Скрипт загружается с defer, фотографии ниже первого экрана — с lazy loading. Для загрузки изображений и шрифтов не нужны внешние соединения. Автопрокрутки отзывов, тяжёлых таймеров и бесконечных анимаций нет.

Lighthouse, Core Web Vitals, профиль CPU и замеры через мобильную сеть/публичный CDN не выполнялись. Быстродействие на реальном хостинге нельзя достоверно вывести из проверки localhost.

### Пути, ссылки и данные

- HTTP-проверены 24 уникальных локальных URL из HTML, srcset, CSS и стандартный favicon: все ответы 200. Проверены совпадение таблиц символов TTF/WOFF и наличие кириллицы в обоих шрифтах.
- Полные страницы пяти источников Unsplash и страница лицензии доступны при проверке; источники вынесены в credits.html и CREDITS.md. См. [лицензию Unsplash](https://unsplash.com/license).
- Сканирование текущих файлов по распространённым шаблонам API-ключей, облачных токенов и приватных ключей не выявило совпадений. Файлов `.env`, `.pem`, `.key` нет. Это проверка текущего дерева файлов, не Git-истории и не формальная гарантия отсутствия любых секретов.
- Email использует демонстрационный домен `.example`, реального адреса и действующего телефона нет. Указаны вымышленная локация и пример графика. Отзывы, мастера, фотографии и режим записи явно обозначены как демонстрационные.
- Формы, отправка персональных данных, аналитика, cookies и серверная запись отсутствуют.

## Перед публикацией

1. После выбора реального URL добавить canonical и og:url, заменить относительный og:image на абсолютный публичный адрес. Не подставлять вымышленный домен. Для подкаталога сохранить завершающий `/` в URL каталога либо открывать index.html.
2. Настроить HTTPS, MIME-типы и кеширование на выбранном статическом хостинге; отдавать только файлы сайта, исключив `.git` и служебные материалы. Никаких конфигураций хостинга в рамках аудита не изменялось.
3. Выполнить smoke-test уже на публичном URL и проверить предпросмотр ссылки.

## Ручная проверка

- Safari/iOS, Firefox и реальный Android; портретная/альбомная ориентация, сенсорные жесты.
- Масштаб 200%, увеличенный системный шрифт, короткий экран в альбомной ориентации, прокрутка длинного диалога на 320 px.
- VoiceOver/NVDA: порядок чтения, объявления отзывов, диалог, skip-link и возврат фокуса.
- Реальные системные `prefers-reduced-motion` и forced-colors.
- Lighthouse и сетевые/полевые метрики на выбранном хостинге.
